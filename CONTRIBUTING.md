# Contributing Guidelines

Thanks for your interest in contributing to this project! These guidelines will help you make contributions that are easy to review and merge.

## How to Contribute

- **Reporting bugs:** Open an issue with a clear title, steps to reproduce, expected vs actual behavior, and any relevant logs or screenshots.
- **Requesting features:** Open an issue and describe the use case, the problem it solves, and an example of the desired behavior.
- **Submitting code:** Fork the repo, create a feature branch from `main` (e.g., `feature/your-feature`), and open a Pull Request against `main`.

## Pull Request Process

- Keep PRs small and focused — one logical change per PR.
- Include a description of what the PR changes and why. Reference relevant issues using `#<issue-number>`.
- Add tests or a screenshot for UI changes when applicable.
- Ensure all checks pass before requesting review.

## Code Style & Best Practices

- Python: follow PEP 8. Use meaningful variable and function names.
- Keep functions small and single-purpose.
- Prefer clear, simple implementations over clever but hard-to-read code.
- Add or update unit tests for bug fixes and new functionality.

## Testing

- If you add functionality, include tests demonstrating expected behavior.
- Run tests locally before opening a PR (if tests exist in the repo).

## Commit Messages

- Use clear, imperative messages, e.g., `Add certificate export feature` or `Fix CSV parsing bug`.

## License and Copyright

- By contributing, you agree that your contributions will be licensed under the project's MIT License.

## Code of Conduct

- Be respectful and constructive. Treat maintainers and contributors with kindness.

## Contact

- If you're unsure where to start, open an issue and label it `help wanted`.
- For questions about contributions, open an issue or mention @GauravKesh in the repo.

Thank you for helping improve this project — contributions are appreciated!
